# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract (per orchestrator lock):** auth screens (sign up, sign in, email-verify pending/confirm, sign-out affordance on every page), the single-scroll fly-submission form, and the author-visible fly detail page (`/flies/[id]`). Public browse/search/catalog/rating UI is explicitly out of scope (Phase 2/3).

**Autonomous-mode note:** This session ran with `AskUserQuestion` disabled. CONTEXT.md and RESEARCH.md pre-answered most engineering/data-shape questions; pure-visual questions (spacing scale, type scale, color values, exact copy strings) had no upstream answer, so sensible defaults were chosen and are flagged `[ASSUMPTION]` below. The executor/checker should treat `[ASSUMPTION]` items as overridable on user request but otherwise binding.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge internal padding |
| sm | 8px | Compact stacks (form field label→input gap, material-row internal gaps) |
| md | 16px | Default element spacing (form field-to-field, card internal padding) |
| lg | 24px | Section padding (form section blocks: Photos / Recipe / Taxonomy / Difficulty / Description) |
| xl | 32px | Layout gaps (space between major page regions: header→content, content→footer) |
| 2xl | 48px | Major section breaks (submit-form section-to-section vertical rhythm on desktop) |
| 3xl | 64px | Page-level spacing (top padding on auth pages, detail-page hero block) |

Exceptions:
- **44px minimum touch target** for all icon-only controls (remove-material-row button, delete-photo button, primary-photo-select control) — accessibility floor, not on the 8-point scale, applied via padding around a smaller icon rather than resizing the icon itself.
- **Photo grid thumbnail cells**: fixed at 96px (multiple of 4, outside the core scale, used only for photo-picker thumbnails).

| Role | Size | Weight | Line Height |

| Heading | 20px | 600 (semibold) | 1.2 |

`[ASSUMPTION]` Exactly 4 sizes (14/16/20/28) and 2 weights (400/600), per design-contract discipline. No upstream artifact specified a type scale.

**Usage mapping for this phase's screens:**
- **Display (28/600)**: page titles — "Create your account," "Submit a fly," the fly name on `/flies/[id]`.
- **Heading (20/600)**: form section headers (Photos, Recipe, Taxonomy, Difficulty, Description), profile page username.
- **Label (14/600)**: form field labels, material-row column headers (Tail / Body / Hackle...), badge text (difficulty pill, fly-type/subcategory/fish-type chips).
- **Body (16/400)**: form input text, description textarea, recipe material free-text, helper/error text, nav links, button labels.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` (light) / neutral-50 background | Page background, form background, card background |
| Secondary (30%) | `neutral-100` / `#F5F5F4` | Section card surfaces (each form section is a bordered card), header/nav bar, sidebar-less page chrome |
| Accent (10%) | `#0F766E` (teal-700, "river" teal) | Reserved for: primary CTA button ("Submit Fly," "Create Account," "Sign In," "Continue with Google/GitHub" outline stays neutral — see note), the star/rating icon fill color (used decoratively on the detail page render, not interactive yet in Phase 1), active nav/tab underline, focus ring, primary-photo selected-state border |
| Destructive | `#DC2626` (red-600) | Reserved for: "Remove photo" / "Remove material row" icon buttons, delete-account-adjacent actions (none in Phase 1 scope), form validation error text and error-state input borders |

Accent reserved for: primary submit/CTA buttons, the selected-primary-photo indicator border/badge, active form-section focus ring, and the star icon fill on the read-only rating display stub on the detail page. **Not** used for body links, secondary/ghost buttons (OAuth buttons render as neutral outline buttons per shadcn `Button variant="outline"` with provider logo, not accent-colored), or decorative chrome.

`[ASSUMPTION]` Exact hex values (teal-700 accent) are a default reflecting a fishing/water-adjacent brand feel appropriate for a fly-fishing catalog; no upstream brand color was specified. Executor may swap the accent hue via the Tailwind `@theme` token without touching this contract's structure if the user later specifies a different brand color — only the hex value changes, the 60/30/10 discipline and reserved-for list stay fixed.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (submit form) | **"Submit Fly"** |
| Primary CTA (sign up) | **"Create Account"** |
| Primary CTA (sign in) | **"Sign In"** |
| OAuth buttons | **"Continue with Google"** / **"Continue with GitHub"** (icon + label, outline button, never accent-colored) |
| Sign out | **"Sign Out"** (text link/menu item in header user-menu, present on every authenticated page per AUTH-06) |
| Empty state heading (photo picker, 0 photos) | **"Add your first photo"** |
| Empty state body (photo picker) | **"Upload at least one photo of your fly. JPG or PNG, up to 6 photos — the first one you choose becomes the cover."** |
| Empty state heading (materials, 0 rows — should not normally occur since form defaults to 1 row) | **"Add a material"** |
| Empty state body (materials) | **"List what you tied this fly with, in order — e.g. Tail, Body, Hackle, Wing."** |
| Error state (form validation, general) | **"Some fields need attention before you can submit."** + inline per-field messages (e.g. "Add at least one photo," "Choose a fly type and subcategory," "Select at least one target fish") |
| Error state (upload failure) | **"That photo didn't upload — check your connection and try again."** |
| Error state (unconfirmed email, submit blocked) | **"Confirm your email to submit a fly."** + secondary action link **"Resend confirmation email"** |
| Error state (auth failure — bad credentials) | **"That email or password isn't right. Try again."** |
| Error state (signup — email already in use) | **"An account with that email already exists."** + link **"Sign in instead"** |
| Email-verification pending state | Heading **"Check your inbox"**, body **"We sent a confirmation link to {email}. Click it to activate your account."** |
| Destructive confirmation (remove photo) | **"Remove photo"**: no modal needed for pre-submit removal (non-destructive to persisted data — it's still a draft); icon-button with `aria-label="Remove photo"`, immediate action, no confirm dialog |
| Destructive confirmation (remove material row) | **"Remove material row"**: same as above — immediate action, no confirm dialog (in-progress form state, not a persisted destructive action) |
| Success payoff (post-submit redirect) | Detail page banner/toast: **"Your fly is live."** (D-02's "see it exists" payoff — shown once on arrival at `/flies/[id]` immediately after submit, e.g. via a `?submitted=1` query flag rendering a dismissible success banner) |

`[ASSUMPTION]` No destructive *data-loss* actions with a confirmation-dialog requirement exist in this phase's scope (no delete-fly, no delete-account UI in Phase 1) — photo/material-row removal are pre-submit draft edits, not persisted deletions, so immediate action without a confirm modal is appropriate per interaction-cost minimization. If Phase 1 planning adds an edit/delete-after-submit flow, that would need a confirm-dialog contract update.

## Component Inventory

Scoped to this phase's three surfaces. All are shadcn/ui primitives (vendored) unless noted.

**Auth screens:**
- `Form`, `Input`, `Label`, `Button` (shadcn, wraps react-hook-form per CLAUDE.md convention)
- `Card` — auth forms are centered single cards, `max-w-md`, vertically centered on viewport
- `Separator` with "or" label between email/password fields and OAuth buttons
- `Alert` (variant `destructive`) for auth error states; `Alert` (default) for the email-verification-pending state
- Provider OAuth buttons: `Button variant="outline"` + lucide-react-adjacent brand mark (Google/GitHub logos as inline SVG, not lucide — lucide has no brand icons; use simple monochrome SVG glyphs)
- User menu (header, every authenticated page): `DropdownMenu` triggered by avatar/initials `Avatar`, containing profile link + Sign Out

**Submit form (`/flies/new`):**
- `Form` + `useFieldArray` (react-hook-form) for the ordered materials section
- `Card` per section (Photos, Recipe, Taxonomy, Difficulty, Description) — each section is a bordered `Card` with a `Heading`-level `CardTitle`
- Photo picker: custom component built on `Input type="file" multiple"`, rendering a thumbnail grid; each thumbnail has a `Badge` "Cover" on the selected primary and a small radio-style click target to reassign primary; destructive `Button variant="ghost" size="icon"` (X icon) per thumbnail
- Material rows: repeated `Input` triplets (label / material / color) inside a flex row, with a drag-handle-free reorder via up/down icon buttons (`ChevronUp`/`ChevronDown` from lucide) — **no drag-and-drop library** in Phase 1 scope, keep it keyboard-accessible
- `Select` (shadcn, Radix-based) for fly type → subcategory cascade (subcategory `Select` disabled until a fly type is chosen)
- `Command`/`Popover`-based multi-select (shadcn "multi-select" composition pattern) or a `ToggleGroup` of `Badge`-styled checkboxes for target fish (multi-select from the seeded ~12 species) — recommend `ToggleGroup type="multiple"` for simplicity at this seed size (12 items fits without needing a searchable combobox)
- `RadioGroup` for difficulty (beginner/intermediate/advanced) — three options, radio is more appropriate than a select
- `Textarea` for free-text description
- Sticky/bottom `Button` (accent) "Submit Fly", disabled while `formState.isSubmitting` or while email is unconfirmed (paired with the unconfirmed-email `Alert`)

**Fly detail page (`/flies/[id]`, author-visible payoff):**
- Photo gallery: primary/cover photo large at top, remaining photos in a smaller row/grid below (`AspectRatio` component from shadcn for consistent image framing)
- `Badge` chips for fly type, subcategory, each target fish, and difficulty
- Recipe rendered as a simple `Table` or definition-list: Hook size, Thread, then ordered material rows
- Description as plain body-text paragraph(s)
- Success banner (`Alert`, dismissible) shown only immediately post-submit per the Copywriting Contract above
- Star rating display: **read-only, non-interactive** in Phase 1 (rating submission is Phase 3) — render as filled/outline star icons (lucide `Star`) showing 0/no ratings yet, with copy "No ratings yet" since RATE-* is out of scope

## Key States

Per surface, the states this phase's UI must design for:

| Surface | Loading | Empty | Error | Success |
|---------|---------|-------|-------|---------|
| Sign up / Sign in | Button shows spinner + disables during submit | n/a | Inline field errors + top-of-form `Alert` for auth-service errors | Redirect (sign-in → intended page; sign-up → verification-pending state) |
| Email verification | n/a | n/a | Invalid/expired token → `Alert destructive` "That link expired — request a new one" | Redirect straight to intended destination (never back to a sign-in prompt, per RESEARCH.md Pitfall 5) |
| Submit form | Submit button spinner; photo thumbnails show per-file compress/upload progress indicator | Photo picker empty state (see Copywriting); materials section defaults to 1 empty row, never shows a true empty state | Field-level validation messages + top summary `Alert`; unconfirmed-email blocking `Alert` | Redirect to `/flies/[id]` with success banner |
| Fly detail page | Server-rendered — no client loading spinner needed (SSR fetch) | n/a (page only reachable for an existing fly) | 404/not-found state if `id` doesn't resolve or isn't owned-visible: standard Next.js `not-found.tsx` | Success banner on first arrival post-submit |
| Header / sign-out | n/a | n/a | n/a | Immediate sign-out redirects to home, header re-renders signed-out state |
