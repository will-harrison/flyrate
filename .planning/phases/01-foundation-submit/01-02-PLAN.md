<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> Next.js (SSR) | Sign-up form submits credentials; session cookies set/read server-side. |
| Next.js middleware -> Supabase Auth | Token refresh on every request; cookie rewrite. |
| Postgres trigger -> public.profiles | SECURITY DEFINER insert during signup; must bypass RLS safely without opening a write hole. |
| anon key in client bundle -> PostgREST/RLS | The anon key is public by design; RLS is the real authorization boundary. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Elevation of Privilege | Missing/late RLS on `public.profiles` exposing/permitting writes via the public anon key | high | mitigate | Task 2 enables RLS in migration 0001 itself; public-read SELECT + owner-only UPDATE `(select auth.uid()) = id` WITH CHECK. Verified by grep for `enable row level security`. |
| T-02-02 | Elevation of Privilege | `handle_new_user()` write hole / signup rollback if RLS blocks its insert | high | mitigate | Task 2 declares the function `security definer set search_path = public` (bounded, single-purpose insert into profiles only) — Pitfall 1 mitigation; no broad definer surface. |
| T-02-03 | Denial of Service | Username collision aborts the entire signup transaction | high | mitigate | Task 2 `on conflict (username)` suffix — a colliding signup succeeds with a suffixed username instead of failing (RESEARCH Open Q1 mitigation (a)). |
| T-02-04 | Spoofing / Information Disclosure | Session silently expires (AUTH-05 broken) because middleware is missing/misconfigured | high | mitigate | Task 1 ships `src/middleware.ts` calling `updateSession()` with the documented matcher; `getUser()` called immediately after client creation (Pattern 2). Verified at Task 4 by hard-refreshing a middleware-matched route (`/u/<username>`) so the check exercises middleware token refresh, not a cached cookie. |
| T-02-05 | Elevation of Privilege | Service-role key reaching the browser bundle | critical | mitigate | Only `NEXT_PUBLIC_SUPABASE_ANON_KEY` is read anywhere; acceptance criteria assert no service-role reference in source. No Phase 1 server-role code path exists. |
| T-02-06 | Tampering | Stored XSS via profile fields rendered on the profile page | medium | mitigate | React escapes text by default; do not use `dangerouslySetInnerHTML` in the profile render path. |
| T-02-SC | Tampering | npm installs (scaffold + deps) pulling a malicious package | high | mitigate | Installs use the exact pinned versions from CLAUDE.md; RESEARCH.md `## Package Legitimacy Audit` documents every package as a false-positive `[SUS]` (canonical GitHub org, `deprecated: false`, no postinstall) — no `[ASSUMED]`/`[SLOP]` package, so no blocking human-verify install checkpoint is required per the audit's documented exception. |
</threat_model>
